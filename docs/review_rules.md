## 공통 원칙

- 서비스는 판정하지 않는다. 관측을 **질문**으로 전달하고 결정은 담당자가 한다 (최종기획서 1장)
- 문구에 "문제·오류·위험·실패·성공·잘못"을 쓰지 않는다 (테스트로 확인)
- 반대 방향 구간이 없다고 "검토가 필요 없다"고 하지 않고, 있다고 "비중을 삭제하라"고 하지 않는다 (워크플로우 8-3)
- 방향이 같은 기간에는 "방향이 달랐다"는 예시 문구를 쓰지 않는다 (12장)
- 전국 근거를 특정 지역 진단처럼 표시하지 않는다 (8-4)
- AI 참고 의견에는 문구(`messages`)가 아니라 수치 없는 상황 설명(`llm_context`)만 넘긴다. 상황 설명에 숫자·`%`·`원`·판정 단어를 쓰지 않는다 (테스트로 확인)
- 결과는 다섯 가지로 구분한다

| 결과 | 뜻 |
|---|---|
| `question` | 담당자 선택이 필요한 질문 |
| `notice` | 오류로 표시하지 않고 해석 조건만 안내 |
| `pending` | 추가 확정 필요 항목 |
| `held` | 근거가 부족해 결론 보류 |
| `not_reviewed` | 이번 범위에서 검토하지 않음 ("문제없음"과 다름). 코드에서는 결과 목록과 따로 담는다 |

조건을 확인했지만 물을 것이 없으면 `no_finding`(확인했으나 해당 없음)으로 따로 표시한다.

## 선택 방식 (4단계)

| 결과 | 4단계에서 |
|---|---|
| `question` | 원안 유지 / 채택 / 수정 / 보류 중 하나를 **반드시** 고른다 (보류도 결정) |
| `notice` | 대안 B(해석 조건 명시)나 원안 유지를 고를 수 있다. **고르지 않아도 다음 단계로 간다** |
| `pending`·`held` | 선택하지 않는다. 보완 기획안 8장(추가 확인사항)에 사유·근거와 함께 자동 기록된다 |
| `not_reviewed` | 문서에 반영하지 않는다 |

| 문서 반영 위치 | 4. 혜택·사용처, 7. 성과 측정계획 |
| 재확인 조건 | 사용처 업종, 대상 연령, 지역 |
| 공유 입력 묶음 | `participation_data` (참여 실적 자료) |
| 데이터 담당 검수 | (날짜) |

지키는 선

- **고른 지역 자료만 쓴다.** 다른 지역이나 더 넓은 범위의 값을 대신 쓰지 않는다.
- 기준값은 코드에 적지 않고 근거 파일(`thresholds.R08.low_share_percentile`)에서 받는다.
- `percentile`과 `regions`가 함께 있는 업종×연령 조합만 비교한다. 일부 조합을 확인하지 못했고 낮은 조합도 없으면 `held`로 둔다.
- 업종별 연령 구성 묶음이 틀리면 그 지역의 R08만 끄고 프로필 카드와 다른 질문은 계속 사용한다.

문서에 들어가는 문장 (대안을 채택했을 때)

| 대안 | 들어가는 곳 | 방식 | 문장 |
|---|---|---|---|
| A 대상 연령이 자주 이용하는 업종도 검토 | 4장 | 덧붙임 | 대상 연령이 자주 이용하는 업종도 사용처 후보로 함께 검토 |
| B 사용처 유지하고 이유 적기 | 4장 | 덧붙임 | 사용처 업종 유지: 대상 연령의 카드 결제 구성과 별개로 사업 목적에 맞는 이유를 기록 |
| C 참여자 연령 확인 자료 추가 | 7장 | 덧붙임 | 참여자 연령 확인 자료: {collect_items} / 수집 담당: {owner} / 확인 주기: {cycle} / 자료 확보 여부: {availability} |

AI 참고 의견용 상황 설명 (`llm_context`, Google AI 요청에 사용)

| 문구 키 | AI에 넘기는 상황 설명 (수치 없음) |
|---|---|
| `question` | 담당자가 고른 사용처 업종 안에서 선택한 대상 연령의 카드 결제 비중이 낮은 편에 든다 |
| `held` | 이 지역은 업종별 연령 구성 자료로 대상과 사용처를 확인하지 못했다 |

## R11 규모와 수용 여건 — 기본 검토

| 항목 | 내용 |
|---|---|
| 실행 조건 (초안) | 축제·행사 기획에서 목표 방문객 수를 적었고, 방문객 수/고른 지역 주민등록인구 비율이 근거 파일의 `R11.visitor_to_resident_ratio` 이상일 때. 기준이 없으면 보류 |
| 결과 | 조건에 해당하면 `question` · 지역 외부 인구 자료가 없거나 쓸 수 없으면 `held` |
| 대안 | A 수용 여건 자료 추가 (8. 추가 확인사항 / 운영 부담 중) · B 목표를 단계별로 나눠 적기 (7. 성과 측정계획) · C 인근 지역과 연계 검토 (8. 추가 확인사항) |
| 문서 반영 위치 | 7. 성과 측정계획, 8. 추가 확인사항 |
| 재확인 조건 | 목표 방문객 수, 지역 |
| 공유 입력 묶음 | `capacity_data` (수용 여건 자료) |
| 데이터 담당 검수 | (날짜) |

지키는 선

- 주민등록인구와 방문객은 같은 집단이 아니다. 질문에는 이 비교가 **목표 규모를 가늠하는 참고**라고 함께 적는다.
- 인구 관측일과 출처 이름을 질문에 표시한다. 카드 자료 기간과 관측일이 같다고 가정하지 않는다.
- 인구로 카드 결제값을 나눈 지표를 만들지 않는다.
- 외부 자료 묶음이 틀리면 그 지역의 외부 기능과 R11만 끄고 카드 자료 질문은 계속 사용한다.

문서에 들어가는 문장 (대안을 채택했을 때)

| 대안 | 들어가는 곳 | 방식 | 문장 |
|---|---|---|---|
| A 수용 여건 자료 추가 | 8장 | 덧붙임 | 수용 여건 확인 자료: {collect_items} / 확인 담당: {owner} / 확인 주기: {cycle} / 자료 확보 여부: {availability} |
| B 목표를 단계별로 나눠 적기 | 7장 | 덧붙임 | 목표 방문객 수를 운영 단계별로 나누고 단계마다 확인 시점을 적음 |
| C 인근 지역과 연계 검토 | 8장 | 덧붙임 | 숙박·주차·교통 수용 여건은 인근 지역과의 연계를 함께 검토 |

AI 참고 의견용 상황 설명 (`llm_context`, Google AI 요청에 사용)

| 문구 키 | AI에 넘기는 상황 설명 (수치 없음) |
|---|---|
| `question` | 목표 방문객 규모가 이 지역 주민등록인구와 같거나 커서 수용 여건 확인 자료가 필요하다 |
| `held` | 이 지역은 외부 인구 자료로 목표 규모를 확인하지 못했다 |
