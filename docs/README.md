> 최신화: 2026-09-21

## 이 폴더는 무엇인가

코드가 읽지 않고 **사람이 읽는 문서**를 모아 둔 곳입니다. 검토 규칙 설명, 서비스 사용법, 제출 PDF에 넣을 화면 캡처처럼 심사위원이나 팀원이 보는 문서가 여기 있습니다.
결정 사항과 진행 기록은 저장소 맨 위 `checks.md`에 두고, 여기에는 중복해서 적지 않습니다.

### `review_rules.md`

규칙 원본인 `src/policy_signal_map/resources/rules/review_rules.json`을 사람이 읽을 수 있게 풀어 쓴 문서다. 두 파일의 규칙 ID·질문·대안은 항상 같아야 한다. 테스트는 규칙 ID 일치만 검사하므로, 문구·문서 문장·상황 설명은 JSON을 고칠 때 사람이 함께 고친다.

규칙마다 다음 표를 채운다.

| 항목 | 내용 |
|---|---|
| 규칙 ID·이름 | 예: R07 금액·비중과 성과지표 확인 |
| 구현 범위 | 검토 구현 / 기본 검토 / 분석 예시 / 향후 기능 |
| 실행 조건 | 어떤 입력값·근거 상태에서 실행되는가 (예: 목표에 비중 확대 포함 + 지표 용도 직접 평가 + R07 applicability allowed) |
| 실행하지 않는 조건 | 예: 지표 용도가 참고 현황이면 직접 평가 오류로 표시하지 않음 |
| 보여줄 근거 | 근거 ID, 비교 A/B 결과, 전국 참고 표시 |
| 질문 문구 | 화면에 그대로 나갈 문장 |
| 대안 | 원안 유지 / 채택 / 수정 / 보류, 대안별 바뀌는 문서 위치·필요 자료·운영 부담 |
| 추가 입력 | 대안 선택 시 받는 값 (수집자료·확보 여부·담당자·주기) |
| 문서 반영 위치 | 보완 기획안의 장·항목 |
| 재확인 조건 | 목표·지역·지표가 바뀌면 다시 확인해야 하는가 |
| 중복 질문 묶기 | R03·R04·R07이 같은 정보를 요구할 때 묶는 방법 (근거 ID는 모두 유지) |
| 데이터 담당 검수 | 근거·해석 한계 문구 확인 여부, 날짜 |

### `usage_guide.md`

제출 PDF와 심사위원용 사용법. 9/17 작성.

- 준비·실행(`run_deploy.ps1`), Vercel + Upstash Redis 배포, AI 참고 의견용 환경변수
- 예시 기획으로 1~5단계 따라 하기(캡처), 단계마다 무엇을 보고 무엇을 고르는지
- 자료가 부족할 때(보류 사례), AI 참고 의견과 모델 고르기
- 저장([결과 저장] Markdown, [PDF로 저장] 브라우저 인쇄, 요청서 저장), 원안을 바꿨을 때(재확인)
- 한계: 합성 수치, 전국 참고, 로컬 서버 재시작 시 상태 초기화(Vercel은 Redis에 24시간 유지), 이럴 때는
- 화면 문구를 인용할 때 외에는 판정 표현을 쓰지 않는다

### `alternatives_comparison.md` (아직 없음)

현재 서비스 기준으로 기존 서비스·공모전 작품을 비교한다 (워크플로우 13장).

- 비교 기준: 자료 적용 범위 확인 / 담당자 선택 / 전체 기획안 반영 / 변경 근거 기록
- 출처는 기존 유사성 검토보고서(`../../검토보고/기존서비스_공모전작품_유사성_검토보고서_20260913.md`)에서 재사용하되 결론은 복사하지 않는다. **9/17 기준 이 보고서는 작업 폴더에 없어 확보가 필요하다**(`checks.md` 6장)
- 확인하지 못한 기능은 "없음"이 아니라 "확인 못 함"으로 적는다
- 각 행에 확인 날짜와 출처 링크를 적는다

### `submission_outline.md` (아직 없음)

제출 PDF 구성안. 최종기획서 10장 평가 관점별로 넣을 증거를 정한다.

- 데이터 활용·분석력: 실제 6개월 관측 → 질문 → 선택 → 문서 변경 (실제 분석 화면은 데이터 담당 확인 후, 공개 저장소에는 넣지 않음)
- 외부자료 활용: 검수한 원문 조건이 기획안 어느 항목에 반영됐는지
- 독창성: `alternatives_comparison.md` 요약
- 실현 가능성: 한 사례의 실제 입력·선택·문서 출력, 정상·자료 부족 처리
- 기대 효과: 측정한 것과 목표를 구분
- 페이지마다 "실제 구현 / 분석 예시 / 향후 기능" 표시

### `screenshots/`

PDF·사용법에 넣을 화면 캡처. **합성 수치 화면만** 둔다. 실제 분석 화면 캡처는 공개 저장소에 올리지 않고 `private/` 또는 팀 비공개 공간에 둔다. 이름 규칙과 다시 찍는 방법은 [screenshots/README.md](screenshots/README.md).
