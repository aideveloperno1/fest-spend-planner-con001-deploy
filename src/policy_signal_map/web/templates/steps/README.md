# `web/templates/steps/` — 단계별 화면 틀

> 최신화: 2026-09-21

## 이 폴더는 무엇인가

1~5단계 **각 화면의 HTML 틀**을 두는 곳입니다. 화면 하나에 파일 하나이며, 모두 공통 바깥 틀(`base.html`) 안에 들어갑니다.
화면에 무엇이 어떤 순서로 보이는지 확인하거나 바꿀 때 이 폴더를 봅니다.

## 파일 목록

| 파일 | 하는 일 (쉬운 말) | 언제 보거나 고치나 |
|---|---|---|
| `input.html` | **1단계 기획 입력** 화면: 단일 컬럼 입력 폼, 하단 고정 입력 상태·진행도·[검토 시작], [예시 기획 채우기]·[모두 지우기] | 입력 칸 배치·안내 문구를 바꿀 때 |
| `evidence.html` | **2단계 근거 확인** 화면: 범위 표시, 요약 문장, 차트 2개, 월별 표, 이웃 달 비교 표, 계산 방법·해석 한계, 자료가 부족한 경우 보기 | 2단계 화면 구성을 바꿀 때 |
| `questions.html` | **3단계 검토 질문** 화면: 질문 카드, 해당 없음·검토하지 않음 목록, AI 참고 의견과 모델 선택 칸 | 3단계 화면 구성을 바꿀 때 |
| `choices.html` | **4단계 보완 선택** 화면: 질문마다 결정 버튼과 보완 방법 카드, 실행 조건 입력, 다시 확인할 선택 안내 | 4단계 화면 구성을 바꿀 때 |
| `draft.html` | **5단계 보완 기획안** 화면: 요약, 장별 문장(바뀐 줄 표시), 추가 확정 필요, 변경 전후 표, 근거 추적, 저장 버튼 | 5단계 화면 구성을 바꿀 때 |
| `document.html` | 5단계 **[전체 문서 보기]**: 저장될 문서 원문 그대로 | 문서 보기 화면을 바꿀 때 |
| `request.html` | 5단계 **정밀 분석 요청서 초안** 보기 (대안 D를 골랐을 때만) | 요청서 화면을 바꿀 때 |

## 자세한 설명 (개발자용)

### 단계와 주소 처리 파일

| 파일 | 단계 | 라우트 |
|---|---|---|
| `input.html` | 1 기획 입력 | `routes/input.py` |
| `evidence.html` | 2 근거 확인 | `routes/evidence.py` |
| `questions.html` | 3 검토 질문 | `routes/questions.py` |
| `choices.html` | 4 보완 선택 | `routes/choices.py` |
| `draft.html` | 5 보완 기획안 | `routes/draft.py` |
| `document.html` | 5 전체 문서 보기 | `routes/draft.py` |
| `request.html` | 5 정밀 분석 요청서 초안 | `routes/draft.py` |

임시 화면 `placeholder.html`은 5단계 구현과 함께 삭제했다.

### 화면별 구성

#### `input.html`

중앙 단일 컬럼 입력 카드 + 하단 고정 바(입력 상태, 진행도, [검토 시작]). 필수·선택 표시, 지역 선택, 예산 미정, 강조 박스(성과지표 선택과 추가 가능한 직접 입력·지표 용도), [예시 기획 채우기]·[모두 지우기].

#### `evidence.html`

시안 S2 기준.
1. 범위 칩: `partials/evidence_badges.html` (전국 참고·기간·자료 버전·합성/실제)
2. 요약 문장 (`web/evidence_view.summary_sentence`): "{기간} 전국 자료에서 비교 가능한 N개 인접 월 구간 중 K개 구간에서 … 변화 방향이 달랐습니다." — K가 0이면 반대로 움직이지 않았다는 다른 문장, 비교 가능 구간이 없으면 보류 문장, 자료가 부족한 구간이 있으면 그 수를 덧붙임 (반대 문구 복사 금지)
3. 차트 2개: 외국인 결제금액(억원) 막대, 외국인 결제 비중(%) 선 + [전체 분모 | 미상 제외] 전환 (`static/js/charts.js`)
4. 월별 표: `partials/month_table.html`
5. 인접 구간 칩 5개: 방향 같음/다름/보류, 작은 차이는 "0.01%p 미만"
6. 계산 방법 카드, 해석 한계 카드 — 두 묶음으로 나눠 표시: **자료의 한계**(근거 파일의 `limitations`, "분석 담당 작성" 표시, 없으면 묶음 생략) / **서비스 해석 원칙**(서비스 고정 문장)
7. [자료가 부족한 경우 보기] 접힘 영역: 보류 레코드 (자료 없음은 0으로 표시하지 않음)
8. [검토 질문 보기 →]

#### `questions.html`

시안 S3 기준. 1단계와 같은 폭의 중앙 단일 열에 검토 의견 N건 (`partials/rule_card.html`)을 표시하고, 각 카드에 근거 칩·"왜 묻나요?"를 둔다. `PSM_LLM_PROVIDER`가 `none`이 아니면 질문 목록 아래 "AI 참고 의견" 영역을 두고, 사용자가 생성 버튼을 누르면 `static/js/opinions.js`가 채운다. 영역 안에는 **AI 모델 선택 칸**(`POST /step/3/ai-model`, 현재 API 키에서 사용할 수 없는 모델은 비활성)과 "모델에 따라 표현이 다를 수 있음" 안내가 있다. 그 아래에는 **확인했으나 해당 없음**, **사업 유형이 달라 확인하지 않음**, **검토하지 않음**을 기본 접힘 상태의 단일 아코디언으로 묶는다. 2~4단계 이동 버튼은 공통 하단 고정 바에 둔다.

#### `choices.html`

시안 S4 기준. 질문별로 결정 칩 [원안 유지] [채택] [수정] [보류] + 대안 카드(바뀌는 곳·필요 자료·운영 부담). 재확인 필요 목록에는 내부 번호 대신 질문 제목을 쓰고, 기획 또는 근거 자료 변경 때문이라고 알린다. 보관한 선택도 질문 제목과 "보완 기획안에는 반영하지 않습니다" 안내만 보인다.

#### `draft.html`

시안 S5 기준. 요약, 장별 문장 목록, 추가 확정 필요, 변경 전후 표, 근거 추적 패널을 보여 준다. 변경 문장과 표는 공개 순번 `변경 001`로 연결하며, 근거 추적 첫 항목에 고른 지역 소비 프로필 요약을 둔다.

**시안과 다른 점:** 두 열 비교(원안 열 + 보완안 열) 대신 **보완안 한 줄 목록 + 변경 전후 표**로 만들었다. 두 열은 좁은 화면에서 어차피 위아래로 접히고, 같은 내용을 두 번 보여주게 된다. 원안 문장은 변경 전후 표의 "원안" 칸에서 확인한다.

#### `document.html`

생성된 Markdown 전체를 읽기 전용으로 표시. [결과 저장] 버튼 동일 제공.

#### `request.html`

시안 "별첨 요청서" 기준. 요청 목적, 분석 대상(미정이면 추가 확정 필요), 기간·단위, 필요 지표, 확인 필요(점포 식별·자료 제공·계약·비용). 제목 아래 고정 문구 "초안입니다. 계약이나 자료 제공이 확정된 것이 아닙니다."
