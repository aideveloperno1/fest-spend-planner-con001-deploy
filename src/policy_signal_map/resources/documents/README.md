# `resources/documents/` — 보완 기획안·요청서 문서 양식

> 최신화: 2026-09-21

## 이 폴더는 무엇인가

5단계에서 저장하는 **보완 기획안 문서와 정밀 분석 요청서의 양식(틀)**을 두는 곳입니다.
양식에는 장 제목, 표 모양, 고정 안내 문장만 있고, 사업명·변경 내용 같은 값은 코드가 채워 넣습니다. 문서 겉모양만 바꿀 때는 코드를 고치지 않고 양식만 고칩니다.

## 자세한 설명 (개발자용)

별첨 3은 `plan.md.j2` 안에 직접 적는다(include하지 않는다). 요청서만 따로 보내는 경우가 있어 `request.md.j2`를 별도 파일로 둔다. 읽는 코드는 `document/render.py`이며 문서를 만들 때마다 양식을 새로 읽는다.

### `plan.md.j2` 구성

```
# 보완 기획안 — {사업명}                (사업명이 비면 "보완 기획안")

> 생성일 {YYYY-MM-DD} · 자료: {시연용 합성 수치 | 자료 버전} · 이 문서는 담당자 확인 전 초안입니다

## 요약
- 변경 N건 · 추가 확정 필요 N건 · 원안 유지 N개 장

## 1. 사업 개요
## 2. 목적·대상
## 3. 일정
## 4. 혜택·사용처
## 5. 모집·정산
## 6. 예산 상태
## 7. 성과 측정계획
## 8. 추가 확인사항

---
## 별첨 1. 변경 전후
| 장 | 원안 | 보완안 | 변경 이름표·검토 질문·대안 | 담당자 선택 | 근거 |       (변경이 없으면 "변경한 항목이 없습니다")

## 별첨 2. 근거와 해석 한계
- 고른 지역 소비 프로필 요약(자료가 없으면 다른 지역으로 넓히지 않고 사유)
- 근거 ID · 범위(전국 참고 등) · 기간 · 자료 버전 · 합성/실제
- 한계 목록

## 별첨 3. 정밀 분석 요청서 (초안)      ← 옵션 D 선택 시만
```

- 변경 줄 끝 표기: `〔변경 · 변경 001〕`. 내부 규칙 번호 대신 문서 순번을 쓰고 별첨 1의 같은 이름표와 연결한다. 추가 확정 필요 값: `**[추가 확정 필요]**`
- 입력에 없는 값은 "원안에 기재 없음 **[추가 확정 필요]**" (`document/describe.py`가 넣음), 장에 줄이 하나도 없으면 "해당 사항 없음"
- 표 칸과 근거 한계에 들어가는 글은 `md_escape`(`|`·백틱 이스케이프), 담당자가 채울 자리는 `mark_pending`(굵게) 필터를 거친다

### `request.md.j2` 구성

- 제목 `# 정밀 분석 요청서 (초안) — {사업명}`, 머리 줄에 작성일과 **"초안입니다. 계약·자료 제공이 확정된 것이 아닙니다."** 고정
- 요청 목적, 분석 대상(참여 점포 목록 `[추가 확정 필요]`), 대상 기간, 필요 지표
- 보내기 전에 확인할 것: 점포 식별 가능 여부, 자료 제공·계약 조건과 비용, 참여자 결제와 점포 전체 결제의 차이 (값은 `document/builder.py`의 `RequestDraft`)
- 지금 자료로 답할 수 없는 것: 참여 점포·참여자 결제 실적 조회 불가, 외국인 전체 기준이라 관광객·거주 외국인 구분 불가 (최종기획서 4-4·5-2)
- 참고한 근거 목록
- 내려받기: `/step/5/download?kind=request`. `plan.md.j2`의 별첨 3과 내용이 겹치므로 문구를 바꾸면 두 곳을 함께 본다

### 원칙

- 양식에 수치를 직접 적지 않는다. 모든 값은 `document/builder.py`가 넘긴다
- "성공", "효과 입증" 등 평가 단정 표현을 쓰지 않는다
- 외부 편집기(메모장, VS Code, Typora)에서 열어 표·목록이 깨지지 않는지 확인한다 (워크플로우 12장 Markdown 내보내기)
